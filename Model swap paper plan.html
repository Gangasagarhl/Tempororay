Why this paper

Each part below gives a short explanation in plain words, then something to try. The parts follow the order the paper's introduction should use.

The question

An AI helper keeps a store of tips. Each tip has a score that says how often it helped. The scores were earned with one model. When that model is replaced, are the scores still right, and what should you do with them on the day of the change?

Try it: four things you can do with a score

Tip A earned a score of 0.90 with the old model. Pick a rule to see what score it starts with under the new model. The numbers are made up.

Score Tip A starts with0.90

Keep: trust the old score fully. It costs nothing, but it is wrong if the new model uses the tip differently.

Wipe: reset the score to the starting value of 0.50. It is safe, but everything learned with the old model is thrown away.

Fixed discount: trust the old score halfway, the same way at every model change. Here 0.90 becomes 0.70.

Calibrated: first run 16 fresh cases with the new model. If the old scores agree with it, trust them more; if not, less. Here the checks set trust to 0.10, so 0.90 becomes 0.54. It costs 16 fresh cases.

The paper measures which of these rules works best across 12 real model changes. A fuller example with four tips is in The idea in one example.

1. A published claim that was never tested

MemRL, accepted at NeurIPS 2026, gave a memory store built with one model to three other models. All three did better. The paper then suggested that the scores themselves carry over to a new model. But it never removed the scores to check, so the gain could come from the stored content alone.

5. How useful an item is depends on the model reading it

A November 2026 preprint (arXiv 2611.03930) measured, for each stored item and question, whether the item helped, once with each of two different models. The two agreed on 225 of 275 cases. Corrected for agreement by chance, that is a Cohen's kappa of 0.58, which is only moderate. If usefulness were fixed, they would agree almost everywhere. The preprint studies no stored scores, so it supports the idea without answering this paper's question.

The idea in one example

A support helper keeps four tips for one kind of failure. Each tip has a score earned with the old model: how often showing it led to a correct answer. When a case arrives, the helper ranks the tips by half relevance and half score, and shows the top one first.

What to notice. With the old model, keeping the scores picks the best tip. With the new model, the same scores push a weak tip to the top. Wiping them falls back on relevance, which is safer but not best. Only re-scoring finds the best tip, and it costs fresh runs on every tip. The paper measures how often each of these happens across 12 real model switches, and how few fresh checks the calibrated rule needs.

Pitch to your manager

Ask for a small, staged approval, not for a paper. A one-week pilot on public data is easy to say yes to, and its result decides the rest.

What to say, in about a minute

"Our tool never trains a model. What it learns is kept as scores beside a language model we rent, and vendors retire those models on short notice. The model under our tool has already changed more than once during development. Published work shows that scored memory still helps after a model is replaced, but nobody has tested whether the scores themselves are still right, or what to do with them. I want to measure that on public benchmarks, with public data and about USD 700 of model calls, and write it up for ICML 2027. It uses no company or customer data. The order of the conversation

  1. Start with the ask and its size. One week, public data, about USD 700, a go or no-go on 22 November.
  2. Say the weak points yourself, first. The link to the product is thin, the paper moves none of the sixteen deliverables, and the scores in the study are not engineers' verdicts. A manager who hears these from you trusts the rest.
  3. Say what the organisation gains. Use the list below.
  4. Give the odds plainly and the stopping rule. About one in four at ICML on the first try if the team includes an author with a prior top-venue paper, and about half that if it does not. What the organisation gains

  • An upgrade check. The study has to build things the project's own audit already lists as missing: a model field on stored items, a token and cost log, and a check that the tool has not silently fallen back to a stand-in model.
  • A tested answer for the next model change. Keep, wipe or discount, with evidence, instead of a guess.
  • Standing. Other hardware companies are publishing agent work on debug and failure analysis. A paper at a machine-learning venue shows competence in the method.
  • A door for the next paper. One accepted paper makes its authors eligible reviewers, which helps the later paper about the tool itself.

The experiment

Open a term to see what it means.

Memory item and score

A stored tip, example or past solution, with a number that says how often showing it helped. MemRL keeps one number per item, called a Q-value. ACE keeps two counters per item, helpful and harmful.

Ordered swap pair

An old model and the new model that replaces it. Haiku 4.5 to Haiku 5.5 and Haiku 5.5 to Haiku 4.5 are two different pairs, because earlier work found the effect can reverse with direction.

Probe table

For each test case, the new model is run once with each candidate item shown on its own, and every answer is graded by a program. The table then holds the true outcome of every choice, so any rule can be scored by looking up the item it would pick.

Noise floor

How much the results move when nothing has changed: a model swapped onto itself, or identical runs repeated. A drop counts only if it is larger than this.

Equivalence test

A test that shows two results are within a set margin, here 3 points. It turns "no drop" into a claim you can defend, instead of a failure to find a difference.

Power prior (the calibrated discount)

A standard statistical way to combine old and new evidence: old evidence counts with a weight between 0 and 1. The calibrated rule chooses that weight from a few fresh checks. It is a known method, so the paper does not claim it as new.

Bootstrap interval

An error bar made by re-sampling the test cases many times. It shows how far a number could move by chance.

Models

Six models in three old-to-new pairs, one from each of three makers, with an open-weight pair that others can re-run after the closed models retire. The planned pairs are Claude Haiku 4.5 to Haiku 5.5, GPT-5.6-luna to GPT-6-luna, and Qwen3.5-27B to Qwen3.8-27B. That gives twelve ordered swaps: three upgrades, three downgrades as a control, and six cross-maker swaps.

The probe table

For every probe task and each of its top four candidate memory items, run the new model twice with exactly that one item shown, and once with no item. Grade by program. Because the table holds the outcome of every candidate, the choice any rule would make can be scored by look-up, with no further model calls.

What you measure

  • Retained validity (the headline). Among pairs of candidates whose outcomes differ, how often did the one with the higher carried score do better? 0.5 is chance. Measure it at home (old scores, old model) and after the swap (old scores, new model), and report the ratio.
  • First-shown success: the success rate of the item each arm would show first.
  • Task success on the final test tasks.
  • Recovery: the number of fresh episodes needed to reach 95% of the ceiling.
  • Cost per arm in calls, tokens and dollars.

Controls and statistics

  • A self-swap of each model onto itself, repeat runs of identical cells, and two independently built banks of the same model set the noise floor. Claim a drop only if it exceeds the self-swap drop.
  • Report every result per ordered pair. Never rely on a pooled average.
  • Use paired comparisons on the same probe tasks, intervals from a bootstrap over tasks and stream orders, and a correction across the four primary comparisons.
  • Test "no drop" as equivalence within 3 points. A failed difference test is not evidence of no drop.
  • Prior cross-model margins are 0.3 to 5 points, so expect small effects. That is why the headline is measured at item level.
  • Repeat a subset of pairs with a second prompt wording. Reviewers of accepted measurement papers criticised reliance on a single prompt.

Three predictions to register

  1. Retained validity rises with the agreement between the two models' outcomes on the same task-and-item cells.
  2. The gap between keep and wipe shrinks as the new model's no-memory success rises.
  3. Scores assigned by the model itself (counters) lose more validity than scores earned from a program's reward (values).

Try it: what each prediction means

In plain words: if the two models succeed and fail on the same cases, old scores should still work.

How it is tested: for each of the 12 switches, measure how often the two models get the same result on the same case and item, then check whether that predicts retained validity.

Why it matters: a team could run a small agreement check before a switch and know in advance whether to keep its scores.

In plain words: if the new model is already good without memory, the choice of rule matters less.

How it is tested: compare the gap between keep and wipe with the new model's success rate when no memory is shown.

Why it matters: it tells teams when the decision is worth any effort.

In plain words: scores the model gave itself should survive a switch worse than scores earned from a program's grade.

How it is tested: compare retained validity for ACE-style counters with MemRL-style values on the same switches.

Why it matters: it gives a practical rule with a reason: trust graded scores more than self-assigned ones.

Each prediction goes into the dated prediction file before the first paid run, and is reported whether it passes or fails.

The go or no-go on 22 November

Run the full study only if all five hold in the pilot:

  1. The old model with its own memory beats no memory by at least 5 points.
  2. Scores mean something at home: concordance of at least 0.60 for at least one score type.
  3. Repeat runs of identical cells disagree less than 15% of the time.
  4. At least 150 items have five or more visits, and at least 30% of probe tasks have candidates whose outcomes differ.
  5. Measured cost per 1,000 calls is within twice the estimate.

Raise the chances

An open gap is needed, but it does not make acceptance likely by itself. ICML reviewers score four things: soundness, presentation, significance and originality. The open gap helps originality and significance. Soundness and presentation come from how well the work is done and written, and committees disagree on about a quarter of papers. That is why even a strong paper with a real gap faces about one in four at ICML on a single try.

    How to say it

    "Our aim is ICML. The realistic expectation is a peer-reviewed paper within about a year of submission, at roughly 60 to 85%. We raise those odds with ten specific actions. We cannot promise any single venue, and nobody can offer 95%."

    Ten actions, ranked

    The ranking is a judgement. The numbers are differences between groups of papers, not proven causes.

    1. Build the author list around real contributors, including one experienced author. Check each author's eligibility, fix every OpenReview profile before 14 January, and protect the reviewing author's time from 24 February to 16 March. Measured At ICLR 2026, 8.8% of one-author submissions were accepted against 24 to 26% for three to five authors (one year of data).
    2. Write the first page for the first-stage reader: the question, what was measured, the headline per pair, the rule, the limits. No format, anonymity or disclosure fault. Re-read the ICML pages in late November, when process updates are due. Official
    3. Close the gaps reviewers name before you submit: a second prompt wording, the no-memory arm, a cost table, the number of items per pair, the noise floor. Measured In a labelled sample of 500 rejected ICLR papers, 48% failed on execution alone.
    4. Claim only what the intervals support, per pair, with limits up front. Official The ICML form says authors "should be rewarded rather than punished for being up front about the limitations".
    5. Release code, prompts, raw answers and probe tables at submission. Measured At ICLR from 2017 to 2025, 44% of papers with code or data were accepted against 33% without.
    6. Prepare the rebuttal in advance and answer every reviewer with numbers. Measured At ICLR 2024 and 2025, 17 to 23% of reviews raised their score after replies and 1% lowered it.
    7. Make it easy to read: short sentences, a figure and main table that stand alone, exact prompts easy to find, written by the authors. Official Presentation is one of four scored dimensions.
    8. Position the paper against the closest work point by point and check every reference by hand. Measured Invented references caused desk rejections at ICLR 2026.
    9. Freeze early, get one experienced outside reader, register the abstract days ahead. Advice At ICLR 2026 the earliest fifth of abstracts was accepted at 31.1% against 22.8% for the last fifth, which is an association only.
    10. Choose the right contribution type and keep the NeurIPS and TMLR versions ready. Official Evaluation papers are accepted at about the conference average.

    Rules of the ladder

    • One venue at a time. Every venue bans parallel review, so each step costs three to six months.
    • Conferences come before TMLR, because TMLR does not take expanded versions of conference papers.
    • A preprint and a workshop paper without published proceedings block nothing. A workshop paper with proceedings would block every later venue.
    • Review is noisy. When NeurIPS gave the same papers to two committees in 2021, they disagreed on 23% of them. A rejection is not proof the paper is weak, and a second submission is the normal path.

    How to present it

    • Title: say "scores", not "memory", because the nearest preprint is titled "Does Your Agent's Memory Survive a Model Upgrade?". Never say "human": every score comes from a program's grade or the model's own marking. Name the measured quantity and do not overclaim; a reviewer of one accepted measurement paper called an overclaiming title its "most serious weakness".
    • Abstract: the forced swap in one sentence, the untested claim, what was measured (models, pairs, benchmarks), the headline number per pair, the rule, the release.
    • First page: the CHIME cell and the MemRL sentence, then the limits stated plainly: program-graded and model-assigned scores, one item shown at a time, single-call tasks.
    • Figure 1: a grid of old model by new model showing retained validity for every ordered pair, with the self-swap diagonal as the noise floor.
    • Main table: one row per ordered pair, one column per arm, with intervals.
    • Related work: a table of what each close paper measured and what it left out.
    • Do not claim as new: moving scored memory across models, comparing own with transferred memory, or the discount rule itself (it is a known statistical device, the power prior).
    • Release: code, prompts, raw answers, score files and probe tables, anonymised and hosted at submission.
